Overview

This guide covers the complete achievement system for CFCMonitor, including all criteria types, the new before/after description feature (v0.4.0.7), and how to properly set up achievements in your AppWrite database.

Current Compatibility: This guide is accurate for CFCMonitor v0.4.0.14 and earlier versions.

AppWrite Collection: Achievements (688bf7d000350d504672)

Achievement Description Types

Simple Description (Traditional)

For achievements where the description remains the same whether locked or unlocked:

{
  "id": "simple_achievement",
  "name": "Simple Achievement",
  "description": "This description shows both before and after unlock",
  "criteria_type": "TOTAL_KILLS",
  "criteria_value": 1
}

Dynamic Description (New in v0.4.0.7)

For "mystery" achievements that reveal more information when unlocked:

{
  "id": "mystery_achievement",
  "name": "First Blood",
  "description": "{"before": "Eliminate your first opponent in combat", "after": "You claimed your first victim in the vast expanse of space"}",
  "criteria_type": "TOTAL_KILLS",
  "criteria_value": 1
}

Important: Dynamic descriptions must be formatted as an escaped JSON string, not a JSON object. The format is:
"{"before": "locked description", "after": "unlocked description"}"

How to Create Dynamic Description Strings

  1. Start with the logical structure: 
    {"before": "Locked text", "after": "Unlocked text"}
  2. Use in your achievement: 
    {
  "description": "{"before": "Locked text", "after": "Unlocked text"}"
}

Basic Achievement Criteria Types

These are counter-based achievements that track cumulative statistics across all gameplay sessions.

TOTAL_KILLS

What it does: Tracks the total number of player-vs-player kills across all sessions
When it triggers: Every time a KILL_EVENT occurs where the player is the killer and victim is another player (not NPC)
How it works:

  • Increments player's PvP kill counter in the database
  • Checks if new total meets or exceeds the criteria_value
  • Unlocks achievement if threshold is reached
  • Note: This is cumulative - kills from different sessions, weapons, and locations all count
{
  "id": "kill_master_10",
  "name": "Kill Master",
  "description": "Kill 10 players in PvP combat",
  "criteria_type": "TOTAL_KILLS",
  "criteria_value": 10
}

TOTAL_DEATHS

What it does: Tracks the total number of times the player has died to other players
When it triggers: Every time a DEATH_EVENT occurs where the player is the victim and killer is another player (not NPC)
How it works:

  • Increments player's PvP death counter in the database
  • Checks if new total meets or exceeds the criteria_value
  • Unlocks achievement if threshold is reached
  • Note: Only counts deaths to other players, not environmental deaths or NPC deaths
{
  "id": "frequent_casualty",
  "name": "Frequent Casualty",
  "description": "Die 25 times in PvP combat",
  "criteria_type": "TOTAL_DEATHS",
  "criteria_value": 25
}

TOTAL_PVE_KILLS

What it does: Tracks the total number of NPC kills across all sessions
When it triggers: Every time a KILL_EVENT occurs where the player is the killer and victim is an NPC
How it works:

  • Increments player's PvE kill counter in the database
  • Distinguishes NPCs from players using internal game identifiers
  • Checks if new total meets or exceeds the criteria_value
  • Note: Includes all types of NPCs (guards, pirates, wildlife, etc.)
{
  "id": "npc_hunter_50",
  "name": "NPC Hunter",
  "description": "Kill 50 NPCs",
  "criteria_type": "TOTAL_PVE_KILLS",
  "criteria_value": 50
}

TOTAL_PVE_DEATHS

What it does: Tracks the total number of times the player has died to NPCs
When it triggers: Every time a DEATH_EVENT occurs where the player is the victim and killer is an NPC
How it works:

  • Increments player's PvE death counter in the database
  • Identifies NPC killers using internal game identifiers
  • Checks if new total meets or exceeds the criteria_value
  • Note: Includes deaths to all NPCs (security, pirates, turrets, etc.) but not environmental deaths
{
  "id": "npc_fodder",
  "name": "NPC Fodder",
  "description": "Get killed by NPCs 15 times",
  "criteria_type": "TOTAL_PVE_DEATHS",
  "criteria_value": 15
}

Weapon-Specific Achievements

These achievements trigger based on the specific weapon used in kill/death events. The system uses internal weapon identifiers from the Assets Collection to match weapons accurately.

PVP_SPECIFIC_KILL_WEAPON

What it does: Unlocks when the player kills another player using a specific weapon
When it triggers: On KILL_EVENT where player is killer, victim is another player, and weapon matches criteria_value
How it works:

  • Extracts weapon information from game logs
  • Strips numerical suffixes from weapon names (e.g., "_1654651")
  • Compares cleaned weapon name against criteria_value
  • Uses internal_key from Assets Collection for accurate matching
  • Note: This is a one-time unlock, not cumulative
{
  "id": "railgun_killer",
  "name": "Railgun Specialist",
  "description": "{"before": "Master a powerful weapon of destruction", "after": "You eliminated an enemy with the devastating railgun"}",
  "criteria_type": "PVP_SPECIFIC_KILL_WEAPON",
  "criteria_value": "kbar_railgun_s5"
}

PVE_SPECIFIC_KILL_WEAPON

What it does: Unlocks when the player kills an NPC using a specific weapon
When it triggers: On KILL_EVENT where player is killer, victim is an NPC, and weapon matches criteria_value
How it works:

  • Similar to PVP weapon kills but specifically checks for NPC victims
  • Useful for weapon mastery achievements against AI enemies
  • Often easier to achieve than PVP weapon kills
  • Note: Great for testing weapon-specific achievement mechanics
{
  "id": "pistol_npc_killer",
  "name": "Pistol Expert",
  "description": "Kill an NPC with a pistol",
  "criteria_type": "PVE_SPECIFIC_KILL_WEAPON",
  "criteria_value": "klaus_p4-ar_pistol"
}

PVP_SPECIFIC_DEATH_WEAPON

What it does: Unlocks when the player gets killed by another player using a specific weapon
When it triggers: On DEATH_EVENT where player is victim, killer is another player, and weapon matches criteria_value
How it works:

  • Tracks what weapon killed the player
  • Useful for "unlucky" or "experience" type achievements
  • Can create interesting social dynamics (players may seek out specific death types)
  • Note: These achievements add humor and can reduce frustration from deaths
{
  "id": "sniper_victim",
  "name": "Sniper's Target",
  "description": "Get killed by a sniper rifle",
  "criteria_type": "PVP_SPECIFIC_DEATH_WEAPON",
  "criteria_value": "behr_p8-ar_sniper_rifle"
}

PVE_SPECIFIC_DEATH_WEAPON

What it does: Unlocks when the player gets killed by an NPC using a specific weapon
When it triggers: On DEATH_EVENT where player is victim, killer is an NPC, and weapon matches criteria_value
How it works:

  • Tracks NPC weapon kills against the player
  • Useful for location-specific dangers (turrets, security forces)
  • Can warn players about specific threats in areas
  • Note: Often tied to exploring dangerous areas or attempting infiltrations
{
  "id": "turret_victim",
  "name": "Turret Fodder",
  "description": "Get killed by an automated turret",
  "criteria_type": "PVE_SPECIFIC_DEATH_WEAPON",
  "criteria_value": "automated_turret"
}

Damage Type Achievements

These achievements track the specific type of damage that caused a kill or death. They help categorize different combat styles and environmental dangers.

SPECIFIC_DEATH_TYPE

What it does: Unlocks when the player dies from a specific type of damage
When it triggers: On DEATH_EVENT where the damage type matches criteria_value
How it works:

  • Analyzes the damage type field from game logs
  • Processes raw damage types into standardized categories
  • Can track environmental deaths, combat deaths, or accident deaths
  • Useful for creating educational or humorous achievements
  • Note: Helps players understand different death mechanics and game world dangers
{
  "id": "collision_victim",
  "name": "Crash Test Dummy",
  "description": "{"before": "Experience the consequences of reckless piloting", "after": "You learned the hard way about collision physics"}",
  "criteria_type": "SPECIFIC_DEATH_TYPE",
  "criteria_value": "collision"
}

SPECIFIC_KILL_TYPE

What it does: Unlocks when the player kills someone using a specific type of damage
When it triggers: On KILL_EVENT where player is killer and damage type matches criteria_value
How it works:

  • Tracks the damage type used to eliminate targets
  • Encourages different combat approaches and tactics
  • Can promote creative killing methods
  • Often tied to specific scenarios or equipment usage
  • Note: Creates variety in combat achievements beyond just weapon-specific kills
{
  "id": "explosive_killer",
  "name": "Demolitions Expert",
  "description": "Kill someone with explosive damage",
  "criteria_type": "SPECIFIC_KILL_TYPE",
  "criteria_value": "explosion"
}

Available Damage Types:

  • melee - Hand-to-hand combat/takedown kills (processed from "TakeDown")
  • collision - Impact/crash damage (processed from "Crash")
  • suicide - Self-inflicted damage
  • vehicle destruction - Vehicle explosion kills (processed from "VehicleDestruction")
  • self-destruct - Self-destruct events (processed from "SelfDestruct")
  • explosion - Explosive ordnance damage (grenades, missiles)
  • bullet - Ballistic projectile damage (firearms)
  • normal - Environmental damage (atmosphere, radiation)
  • suffocation - Oxygen deprivation
  • bleed out - Bleeding to death (processed from "BleedOut")
  • blunt force - Blunt trauma damage
  • punish - Punishment system damage
  • hazard - Environmental hazards
  • electric arc - Electric damage (processed from "ElectricArc")

Event-Specific Achievements

These achievements trigger on specific game events regardless of other factors like weapons or locations. They track unique gameplay moments and special circumstances.

CRASH_EVENT

What it does: Unlocks when the player experiences a game crash
When it triggers: On CRASH_EVENT where player is the client_player_name
How it works:

  • Automatically triggered when the game client crashes
  • Logged by the system when game termination is detected
  • Can be used for "survivor" type achievements that add humor to technical issues
  • Helps track stability issues while rewarding players for persistence
  • Note: Turns a negative experience into a positive achievement moment
{
  "id": "crash_survivor",
  "name": "Crash Survivor",
  "description": "Survive a crash event",
  "criteria_type": "CRASH_EVENT",
  "criteria_value": ""
}

SUICIDE_EVENT

What it does: Unlocks when the player commits suicide in-game
When it triggers: On SUICIDE_EVENT where player is the client_player_name
How it works:

  • Triggered when player intentionally kills themselves
  • Different from accidental deaths or deaths to other players
  • Can track deliberate self-elimination for tactical or other reasons
  • Often used for dark humor achievements
  • Note: Empty criteria_value since the event itself is the trigger
{
  "id": "self_destruct",
  "name": "Self-Destruct",
  "description": "Take your own life",
  "criteria_type": "SUICIDE_EVENT",
  "criteria_value": ""
}

SELF_DESTRUCT_EVENT

What it does: Unlocks when the player self-destructs their ship
When it triggers: On SELF_DESTRUCT_EVENT where player is the client_player_name
How it works:

  • Specifically tracks ship self-destruct sequences
  • Different from general suicide - this is vehicle-specific
  • Often used as a last resort in combat or to prevent capture
  • Can be strategic in certain scenarios
  • Note: Distinct from other death types as it's a deliberate ship destruction
{
  "id": "ship_destroyer",
  "name": "Ship Self-Destructor",
  "description": "Self-destruct your own ship",
  "criteria_type": "SELF_DESTRUCT_EVENT",
  "criteria_value": ""
}

SUFFOCATION_DEATH_EVENT

What it does: Unlocks when the player dies from suffocation/oxygen deprivation
When it triggers: On SUFFOCATION_DEATH_EVENT where player is the client_player_name
How it works:

  • Triggered when player runs out of oxygen in space or hostile environments
  • Common when EVA suits fail or life support systems are damaged
  • Educational achievement teaching about environmental dangers
  • Often happens during exploration or after ship damage
  • Note: Specific to oxygen-related deaths, not general environmental damage
{
  "id": "no_air_casualty",
  "name": "Suffocation Victim",
  "description": "Die from suffocation",
  "criteria_type": "SUFFOCATION_DEATH_EVENT",
  "criteria_value": ""
}

IN_APP_FEATURE

What it does: Unlocks when the player accesses hidden features, easter eggs, or special functions within the application
When it triggers: Either on IN_APP_FEATURE_EVENT with matching feature_name, or retrospectively when checking player_stats
How it works:

  • Real-time: Triggered when IN_APP_FEATURE_EVENT is fired with specific feature_name in event_data
  • Retrospective: Checks if player has the specified feature field set to true in player_stats database
  • Used for easter eggs, secret menus, cheat codes, hidden areas, developer features
  • Encourages exploration of the application's hidden functionality
  • Note: Criteria_value should match the feature identifier used in your code
{
  "id": "space_invaders_discoverer",
  "name": "Space Explorer",
  "description": "{"before": "Discover a hidden feature within the application", "after": "You found the Space Invaders easter egg!"}",
  "criteria_type": "IN_APP_FEATURE",
  "criteria_value": "easter_egg_1"
}

IN_APP_FEATURE Implementation Details:

  • Feature Naming: Use descriptive identifiers like "easter_egg_1", "secret_menu", "developer_mode"
  • Database Fields: For retrospective checking, ensure boolean fields exist in player_stats
  • Event Triggering: Fire IN_APP_FEATURE_EVENT when features are accessed
  • Case Sensitivity: Feature names are case-insensitive but should be consistent
  • Multiple Features: Create separate achievements for each distinct feature

Combination Achievements

These advanced achievement types combine multiple criteria into a single achievement, allowing for very specific and challenging unlock conditions.

How it works:

  • Requires BOTH weapon and location to match simultaneously
  • More challenging than single-criteria achievements
  • Creates location-based weapon mastery challenges
  • Encourages players to visit specific areas with specific loadouts

Custom Criteria (Advanced)

The most powerful and flexible achievement system that allows you to create complex achievements with multiple conditions, custom logic, and advanced matching rules.

What Custom Criteria Does

Purpose: Create achievements with any combination of conditions that aren't possible with standard criteria types
Flexibility: Supports multiple conditions, array matching, AND/OR logic, and complex scenarios
Power: Can create achievements like "Kill any Hornet variant with explosive damage at Port Olisar while the victim is a specific player"
Use Cases: Advanced challenges, specific scenario rewards, complex tactical achievements

How It Works Internally

  1. Event Processing: When any relevant event occurs, the system checks all CUSTOM_CRITERIA achievements
  2. Condition Matching: Each condition in the criteria is evaluated against the event data
  3. Logic Application: Uses all_conditions_required (true=AND, false=OR) to determine if achievement unlocks
  4. Asset Resolution: Automatically resolves internal_key values from Assets Collection for accurate matching
  5. Array Support: Can match against multiple values using array notation

Basic Structure

{
  "criteria_type": "CUSTOM_CRITERIA",
  "criteria_value": "{"event_types": ["KILL_EVENT", "DEATH_EVENT"], "conditions": {"killer": "player_handle", "victim_type": "npc", "weapon": "specific_weapon_name", "location": "specific_location_name", "damage_type": "explosion"}, "all_conditions_required": true}"
}

Important: The criteria_value should be a JSON object. AppWrite will handle the proper formatting automatically.

How to Construct CUSTOM_CRITERIA Objects

The criteria_value for CUSTOM_CRITERIA should be a JSON object. Here's how to build them:

Basic Structure Example

{
  "event_types": ["KILL_EVENT"],
  "conditions": {
    "killer": "player_handle",
    "victim_ship_id": "ANVL_Hornet_F7C",
    "damage_type": "vehicle destruction"
  },
  "all_conditions_required": true
}

Use in Achievement

{
  "id": "your_achievement_id",
  "name": "Achievement Name",
  "description": "Description text",
  "criteria_type": "CUSTOM_CRITERIA",
  "criteria_value": "{"event_types": ["KILL_EVENT"], "conditions": {"killer": "player_handle", "victim_ship_id": "ANVL_Hornet_F7C", "damage_type": "vehicle destruction"}, "all_conditions_required": true}"
}

Available Conditions Explained

Player/Target Conditions

  • killer: Who performed the kill
    • "player_handle" = Must be the current player
    • "specific_name" = Must be a specific player/NPC (uses cleaned internal_key)
    • ["name1", "name2"] = Must be one of multiple specific names
  • victim: Who was killed/affected
    • Same options as killer
  • victim_type: What type of entity was affected
    • "npc" = Victim must be an NPC
    • "player" = Victim must be a player
    • "any" = Any victim type accepted

Asset-Based Conditions

  • victim_ship_id: Partial matching for ship names
    • "HORNET" = Matches any ship with "HORNET" in internal_key
    • ["A1_Spirit", "HORNET"] = Matches ships containing either string
  • weapon: Specific weapon matching
    • "kbar_railgun_s5" = Exact weapon match
    • ["railgun", "sniper"] = Matches any weapon in the array
  • location: Specific location matching
    • "port_olisar_station" = Exact location match
    • ["station1", "station2"] = Matches any location in the array
    • "explosion" = Exact damage type match
    • ["explosion", "collision"] = Matches any damage type in the array

Logic and Event Control

  • all_conditions_required: Controls condition logic
    • true = ALL conditions must be met (AND logic)
    • false = ANY condition can be met (OR logic)
  • event_types: Which events can trigger this achievement
    • ["KILL_EVENT"] = Only kill events
    • ["KILL_EVENT", "DEATH_EVENT"] = Either kill or death events

Logic Options

  • all_conditions_required: true (AND logic) or false (OR logic)
  • event_types: Array of valid event types

Vehicle and Weapon Count Achievements (Advanced Tracking)

Starting in version 0.4.0.10, CFCMonitor includes advanced tracking of kills and deaths per vehicle and weapon using the tracker_weapons_ships system. This enables achievements like "Get 10 kills against players in Hornet ships", "Get 5 kills with the FS9 LMG", "Die 10 times in Aurora variants", or "Get killed by energy weapons 5 times".

Available Count Criteria (as of v0.4.0.14):

  • count_vehicle_kills - Track kills against players flying specific vehicles
  • count_weapon_kills - Track kills using specific weapons
  • count_vehicle_deaths - Track deaths while flying specific vehicles (NEW)
  • count_weapon_deaths - Track deaths caused by specific weapons (NEW)

Database Setup Required

Before using count-based achievements, you must add the tracking attribute to your Appwrite database:

  1. Navigate to: Appwrite Console → Databases → Your Database → player_stats Collection
  2. Add New Attribute:
    • Attribute Name: tracker_weapons_ships
    • Type: object (JSON)
    • Required: false (unchecked)
    • Default Value: {} (empty object)
  3. Save the attribute

How the Tracking System Works

The system automatically tracks kill/death statistics for every vehicle and weapon interaction:

{
  "tracker_weapons_ships": {
    "vehicles": {
      "ANVL_HORNET_F7_MK2_COLLECTOR_MOD": { "kills": 7, "deaths": 3 },
      "ANVL_Hornet_F7A_Mk2_Exec_Stealth": { "kills": 2, "deaths": 1 }
    },
    "weapons": {
      "FS9_LMG": { "kills": 5, "deaths": 0 },
      "P4_AR": { "kills": 3, "deaths": 2 }
    }
  }
}

What gets tracked:

  • Vehicle Kills: When you kill someone, their vehicle type is recorded
  • Vehicle Deaths: When you die, your vehicle type is recorded
  • Weapon Kills: When you kill someone, your weapon is recorded
  • Weapon Deaths: When you die, the weapon that killed you is recorded

Important Notes

  1. Automatic Tracking: The system automatically tracks all kills/deaths with vehicles and weapons - no additional setup needed beyond the database attribute.
  2. Retroactive: Existing player data won't have historical vehicle/weapon stats. The tracking starts from when you implement this system.
  3. Internal Key Matching: The system uses both exact matches and internal key resolution from the Assets Collection for flexible matching.
  4. Performance: Count checks are performed efficiently using database queries and are cached for performance.
  5. Event Type Requirements:
    • count_vehicle_kills and count_weapon_kills only trigger on KILL_EVENT where the player is the killer
    • count_vehicle_deaths and count_weapon_deaths only trigger on DEATH_EVENT where the player is the victim
    • Mix event types for complex achievements requiring both kills and deaths
  6. Debugging: Enable debug logging to see count checking in action: 
    [DEBUG] count_vehicle_kills check: vehicle=ANVL_HORNET_F7_MK2_COLLECTOR_MOD, required=10, actual=7, met=false
[DEBUG] count_weapon_deaths check: weapon=KLWE_LaserRepeater_S3, required=5, actual=3, met=false

If you have existing single-kill achievements that you want to convert to count-based:

Asset Names Reference

Damage Types

Use these processed damage type names:

  • takedown - Melee kills/deaths
  • collision - Impact/crash damage
  • suicide - Self-inflicted damage
  • vehicle destruction - Vehicle destruction events
  • selfdestruct - Self-destruct events
  • suffocation - Oxygen deprivation deaths
  • bleed out - Bleeding out deaths
  • bullet - Ballistic projectile damage
  • explosion - Explosive damage
  • normal - Environmental damage
  • punish - Punishment system damage
  • blunt force - Blunt force trauma damage

Important Notes

  • All asset names use internal_key values from your Assets Collection
  • Damage type comparisons are case-insensitive
  • System automatically strips numerical suffixes (e.g., "_1654651")
  • For CUSTOM_CRITERIA, use internal_key values, not display names
